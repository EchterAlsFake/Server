2. Local app processing and website operational statistics

Porn Fetch runs locally and does not send browsing history or records of downloaded videos to my server. This is separate from requests to this website, downloads of application files and updates, and the separately described purchase, licensing and optional diagnostic processes.

Daily visitor counting

A self-hosted dashboard estimates daily visitors per host. It processes the connection IP address in memory with the UTC date and a secret key to form a check value. The counting table stores a derived hash, date, host and fixed group “page”, not the plain IP address. The secret key itself is not currently replaced daily. This is pseudonymisation, not guaranteed anonymisation.

The same IP can produce matching check values on multiple own domains on the same day because the calculation does not include the hostname. Reporting uses aggregate counts, not individual interest profiles. Shared or changing IP addresses may distort counts. Each new counting operation deletes check values dated before the current UTC date minus two days. Without further counting, this cleanup does not run; there is no independent deletion job. Daily and host totals remain. Backups are handled separately.

Application downloads and updates

The reverse proxy keeps separate access logs for application files and update paths, including timestamp, host, file path without URL parameters, request method, response status and transfer volume. IP fields are replaced by hashes; request and response headers are removed. These IP check values are not protected by a daily-changing secret and can match across days. The logs must therefore not be described as generally anonymous.

The download statistics importer stores IP check values with the day, file path and download source in a separate working database to count requests, partial transfers, data volume and distinct downloaders. This concerns software/update files, not videos downloaded using the app. The current importer has no automatic deletion job for these records. Log rotation is configured for 20 MiB, at most ten archived files and a seven-day age limit for rotated files; this does not guarantee deletion of every entry in the active log or statistics database after seven days.

The purposes are operation, troubleshooting and usage measurement of my own services, based on legitimate interests under Art. 6(1)(f) GDPR. These statistics are not intended for disclosure to advertising networks. You may object on grounds relating to your particular situation (section 10). The application's separate request and transfer counters contain only totals.
